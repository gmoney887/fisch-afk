# Reliable gameplay feedback loop: implementation and validation

The user's four-stage plan is the source of intent. Preserve the entire dirty working tree. Keep C#/.NET, WPF, OpenCvSharp, CPU-only Windows x64 delivery, and one visible Roblox session per PC. Users join, choose a position, and equip a rod. Navigation, rejoining, purchases, and progression remain outside this milestone. Never publish without an explicit request.

## Acceptance requirements

1. Improve confirmed catches per wall-clock hour on both PCs. Use one coordinator for input/workflow ownership, replaceable frame/input/clock boundaries, timestamped evidence, confirmed/failed/unknown outcomes, detected prerequisites and results, bounded retries, three recovery attempts per incident, and explicit resume after interruption. No fallback clicks or inferred empty inventories. Finalize delayed catches exactly once. Release held inputs on stop, focus/minimize/capture/geometry/DPI interruption.
2. Record all workflows and passive demonstrations: raw ROI/context images, inputs, decisions, confidence, outcomes, monotonic timestamps/frame IDs, and dropped entries. Version metadata and record geometry/settings/adaptation. Keep queues bounded; target 15 seconds before and five after failures, sampled successes, seven-day/1 GB retention with marked examples inside the budget. Provide replay, labels, detector comparisons, fixture export, and session/PC-separated evaluation.
3. Normalize controller geometry, use real elapsed time/freshness, estimate cast and reel pull/release response, reject uncertain/stale samples, bound tuning, preserve compatible validated profiles, and reset for changed dynamics/geometry. Developer-review shared detector/template changes. Unknown interfaces pause with evidence. Compare catches/hour and separate reward outcomes/time costs.
4. Provide private GitHub diagnostics with reviewed media/text, optional description, selected clips, one send action, a configured private repository and repository-scoped Issues/Contents write token in Credential Manager. Use a diagnostics release asset plus linked issue, at most 20 MB, an explicit reduced bundle, session-time metadata, frozen retry state, visible errors, and manual export. Keep portable builds, non-destructive configuration migration, Windows CI, update notification, and rollback builds.

Replay validates perception and recorded decisions; it cannot prove outcomes from different inputs. Before release, require Windows build/tests, no false success on labeled negatives, immediate stop release, two unattended hours on each PC without manual recovery, and repeated matched comparisons across rods, resolutions, DPI, bright scenes, delayed banners, missing dialogs, empty inventories, stale frames, cancellation, and upload retries.

## Local live check

1. Start the validation executable. Close any previous macro instance first to avoid competing hotkeys/input.
2. With Roblox ready, click **Observe**, demonstrate the aquarium and crate interfaces (including empty inventory), and press **End**. Observation sends no gameplay actions. Full-viewport context is sampled at one frame per second; hold important UI states for several seconds.
3. Open **Submit**, select the completed session, and choose **Replay / label**. Review raw frames, save state/outcome/target labels, and export fixtures with their provenance. Selecting frames in Submit and applying a pixel mask controls exactly which PNGs are included; selecting none makes a text-only report. Legacy AVI can still be exported through the service, but the private dialog intentionally excludes unpreviewed video.
4. Run a short fishing trial with reward automation disabled until reviewed workflow templates exist. Verify End releases inputs immediately, switching focus pauses, and resume is explicit. Then collect matched baseline/adaptive sessions separately.
5. For reporting, configure a private repository with a pre-existing `diagnostics` release and a repository-scoped token. No token is stored in config or diagnostic ZIPs. If an issue POST has an uncertain result, retry reconciles by report marker and refuses to create a duplicate when reconciliation fails.

## Remaining work and evidence

- **No reviewed aquarium/crate templates exist.** First-PC demonstrations now expose incorrect crate geometry and a quantity field instead of the assumed Max button. Reward dismissal and the equipment/activation sequence also need revision. See [live observations](LIVE-OBSERVATIONS-2026-09-18.md); do not enable the current contracts by simply adding templates.
- Three first-PC passive sessions captured 52 frames without reported drops. Aquarium claim evidence, focus-loss pauses, and an End stop were observed. The macro obscures crate reward text. Passive stop does not validate held-input release latency, and no actual automated fishing trial has been reviewed. Native computer-use runtime tools are unavailable in this task. Both two-hour trials and the entire second-PC evidence set remain outstanding.
- Casting response estimation and extraction of the whole reel decision loop into a replayable pure controller are unfinished. Pull/release candidates are not demonstrated improvements. Current replay comparison stores detector outputs; it is not a complete multi-version evaluation runner.
- Labels are currently raw-frame state/outcome/target bounds. The UI provides frame selection rather than timed video clips, manual single-rectangle masking rather than automatic name/chat redaction, and frame stepping rather than timed playback. Improve these based on actual usage.
- Failure capture can retain five seconds only while Roblox remains focused with unchanged geometry. On focus loss/minimize/invalid capture, release is immediate and the tail is truncated, not silently described as complete.
- Retention preserves marked sessions preferentially, but the global budget takes priority. Active raw queue: 48 MB plus one frame being encoded; rolling disk frames: 64 MB; preserved frames: 128 MB/5,000 frames; journal: four 4 MB segments. Complete frame metadata remains in `frame-index.json` after journal rotation. Frozen exports are retained for retry; storage saturation rejects additional recording/export with an error. Concurrent multi-instance storage use is not supported.
- Credential Manager integration and real GitHub uploads have not been exercised with credentials. Mock HTTP tests passed. Application update notification already existed; packaging now stages replacements and preserves the previous portable folder, but the rollback script has only received a syntax check. The direct self-contained Windows publish is verified separately.

Do not call this implementation release-ready until these gaps and the original acceptance evidence are closed.
